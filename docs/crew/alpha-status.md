# Crew alpha status

Snapshot: `main` at `359740f`. Built from the docs, follow-ups and designs, checked against the
code and live runs. Active work is tracked in [implementation-plan.md](implementation-plan.md); suites in
[armory-suite-proposals.md](armory-suite-proposals.md); measurements in
[gondolin-benchmark.md](gondolin-benchmark.md).

Verdict: the runtime core is solid for an alpha. The three gaps most likely to bite in real use are
in-memory lifecycle state, incomplete failure-path evidence, and deferred backend coverage. The
product focus is runtime and tooling; Claude Code skill migration is out of scope.

## Complete

| Area          | What exists                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime       | Main launches a separate Crew host, then member Pi sessions each in its own VM with a private workspace seeded from the repository revision. Transactional launch with rollback, evidence archived before cleanup, and a launch that fails fast when a worker exits before ready.                                                                                                                                                  |
| Dispatch      | Dependency dispatch with idempotency. Initial work and resumed work share `maxParallel`; queued resumes start when a slot is available.                                                                                                                                                                                                                                                                                            |
| Comm          | The active host reports events and status to Main. `crew_message` resumes a waiting member for one turn; the older Comm/Lifecycle extension is retained for backend scale-up but is not loaded.                                                                                                                                                                                                                                    |
| State         | Each member has one current lifecycle state (`queued`, `held`, `running`, `ci`, `needs_input`, `failed`, `on_hold`, `completed`, `handed_off`, or `cancelled`), with current-status, hold, handoff, report, and CI evidence.                                                                                                                                                                                                       |
| TUI           | Per-Crew footer, structured dashboard with real tables and chrome, Crew picker.                                                                                                                                                                                                                                                                                                                                                    |
| Isolation     | Per-worker Gondolin VM, no host fallback; libkrun by default with QEMU fallback (`HALL_VMM`), idle release, a private guest workspace, and deny-by-default guest networking.                                                                                                                                                                                                                                                       |
| Armory        | The host registers the Armory tools a Crew needs. A member can call exactly the tools its role and roster entry declare; Crew keeps no tables of Armory operations and checks no tool input; the runner's salvage and CI verification need specific operations (`member-agent.mjs`) and run only if the member was granted all of them. Verified, read-only dependency sources and Prettier are available to bash-granted members. |
| Credentials   | `HALL_GITHUB_TOKEN` stays on the host. Crew does not inspect tool input; the host token's scope bounds what a granted call can reach.                                                                                                                                                                                                                                                                                              |
| Observability | Per-worker metrics, static context tokens, event logs.                                                                                                                                                                                                                                                                                                                                                                             |
| Quality       | Required CI runs the suite, extension-load test, and format check with QEMU. Its separate CI skip-policy step is unskippable and constrains the temporary krun title skip to four QEMU-paired cases.                                                                                                                                                                                                                               |
| Optional      | GitHub Discussion adapter, on demand.                                                                                                                                                                                                                                                                                                                                                                                              |

## Needs refinement

| Area         | Gap                                                                                                                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lifecycle    | State is in memory. `blocked` takes no structured reason. The state machine is specified in `architecture.md` and `lifecycle-state-contract.md`. Retry is not a linked attempt.                                                             |
| Network      | Guest networking is deny-by-default. The host-held token never enters the VM; its scope, rather than Crew input inspection, bounds reachable host-side calls.                                                                               |
| CI           | Linux krun coverage remains deferred in [#160](https://github.com/MockaSort-Studio/pi-automata-crew/issues/160); the required QEMU path and its unskippable skip-policy guard remain in place. See the [CI skip policy](ci-skip-policy.md). |
| Launch paths | Launch-failure roster retirement is tested (`environment-startup.test.mjs`) and owner death runs through a real `start_crew` (`start-crew-owner-death.test.mjs`).                                                                           |
| Credentials  | No renewal or rotation. The host token's scope is the remaining bound on what granted GitHub calls can reach.                                                                                                                               |
| GitHub suite | `github_issue_update` takes a free-form `state`. The earlier audit flagged issue-state mutation, Project item identity and list contracts; not rechecked in the Armory suite. Discussion reply pagination is open.                          |
| Memory       | About 295 MB per active worker (libkrun). Lower needs a policy decision on isolation.                                                                                                                                                       |
| Startup      | `session_start` boots a VM at launch, because tool descriptors are not embedded in the release.                                                                                                                                             |
| Portability  | libkrun tested on one macOS arm64 machine. The preflight has no KVM check, so a Linux host without KVM would fail at VM start instead of falling back.                                                                                      |
| Docs         | `follow-ups.md` is 452 lines, mostly history still labelled "Historical unresolved".                                                                                                                                                        |

## Missing

| Area               | Gap                                                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Lifecycle          | Durable service, audit log, crash recovery (plan items 5 and 8).                                                                                                         |
| Retry              | No durable linked-attempt model: `crew_message` normally resumes the same session; handoff recovery starts a new session with runner-recorded evidence.                  |
| Model policy       | No selection by task risk, no budgets (item 16).                                                                                                                         |
| Evidence           | No baseline, A/B quality gate, or serial-versus-Crew benchmark (item 17).                                                                                                |
| Setup              | `/hall-setup` (item 18).                                                                                                                                                 |
| Runtime roadmap    | Heartbeat snapshots and deadline-aware replanning have no implementation. Claude skill migration is explicitly out of scope.                                             |
| Hall CLI port      | Project progression, Issue closure, dependency management, GitHub adapter contracts.                                                                                     |
| Suites             | The npm suite lives in hall-armory as `coding/npm` and is still unpublished; CI inspection, workflow lint, `act`, `dev/tasks`, prettier, `yq`, and `jq` remain deferred. |
| Network and `bash` | Default-deny egress, denied-host logging, `bash` telemetry, a `bash`-less `reviewer`.                                                                                    |
| Armory release     | Lead-time measurement, suite scaffold, local harness, launch-time catalog check.                                                                                         |
| Backend            | Backend scale-up is deferred in #54; the queued-message feature is also deferred.                                                                                        |
| Platforms          | Linux and Windows validation. Terraform suite and VM snapshots are deferred.                                                                                             |

## Measured this cycle

| Question                        | Answer                                                                                                                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where does a worker's memory go | The VMM. libkrun 55 MB idle and 100 MB after a workload, QEMU 151 and 212 MB. Guest RAM size and base image make no difference (the guest uses about 80 MB).                          |
| Active sandboxed worker         | About 295 MB with libkrun (about 400 MB QEMU) plus 64 MB of servers per Crew; about 140 MB once the VM is released; a host worker about 134 MB.                                       |
| Why a sandboxed Pi is larger    | 54 MB of live VM client state, freed on release; not the SDK import.                                                                                                                  |
| Cold and warm timings           | Armory closure 10 s cold; worker ready 0.6 s (host) and 0.5 to 1.5 s more with a VM; `gh` call 93 ms; real GitHub call about 1.0 s (libkrun). The guest image download was not timed. |
| `act` in the guest              | Host mode works without Docker; this repo's `ci.yml` job passed in 3.9 s. The guest is musl-only, with no glibc.                                                                      |
| Typed tool versus `bash`        | A typed tool costs about 130 tokens of schema per turn; `act` output is about 2,700 tokens raw against about 100 compact.                                                             |
| microvm.nix                     | Not adopted: it has no exec API, programmable filesystem, or network interception with secret placeholders.                                                                           |
