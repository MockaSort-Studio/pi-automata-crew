# GitHub CI metadata egress

Members with an explicit workflow-list or workflow-view Armory grant may make GET requests to the corresponding Actions run and job metadata endpoints for their authorized repository only. This is not general GitHub access. Only `page` and `per_page` numeric pagination parameters are accepted. Other paths, log downloads, redirects and signed storage hosts are denied. The guest receives a Gondolin placeholder in `GH_TOKEN`, not the host token; requests must use `Authorization: Bearer $GH_TOKEN`.

Use the existing host-side `github_workflow_run_failed_log` operation for failed-step logs. Its output is limited to the last 12,000 characters (or the requested smaller limit), followed by a truncation marker when applicable. Earlier failure details can be missing; full log access is not implemented.

Crew's repository authorization accepts the released optional inputs of the host-side workflow reads, with bounds, before Armory validates them again. `github_workflow_run_view` accepts `artifacts` (boolean). `github_workflow_run_failed_log` accepts `jobId`, `artifactId` and `startLine` (positive safe integers), `step` (1 to 1000), `maxLines` (1 to 2000), `maxChars` (1 to 12000), `startChar` (0 to 4194304), `firstFailure` (boolean), `artifactName` (1 to 256 characters) and `artifactPath` (1 to 1024 characters, a plain relative path: no leading slash, drive letter, backslash, empty, `.` or `..` segment, or control character). Any other key is refused, and both still require the authorized repository. Logs and artifacts are fetched host-side; guest egress never reaches their endpoints. `tests/runtime/repository-authorization-drift.test.mjs` fails when a released input of a guarded operation is neither accepted nor explicitly refused.

This boundary covers guest CI metadata and the newly admitted host-side workflow reads only. It does not provide comprehensive repository confinement for every existing Armory tool; in particular, the pre-existing `github_issue_view` cross-repository gap is outside this change.

The guest network uses Gondolin's request hooks and secret manager. VM release revokes the old placeholder; an idle restart creates a fresh one. The per-hop hook rejects redirects after substitution rather than forwarding a credential. Independent security review is required before merging this boundary.
