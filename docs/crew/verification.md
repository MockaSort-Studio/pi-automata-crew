# Crew verification and dependency sources

A bash grant permits commands in the member's Gondolin guest; it does **not** promise Git, a package manager, project dependencies, or any particular test runner. Inspect the member's verification prerequisites before choosing checks. `node --check path/to/file.mjs` is a syntax check when guest Node is present, not a project test.

For members granted bash, Crew attempts an anonymous, bounded HTTPS fetch from `registry.npmjs.org` for the reviewed exact pins in `extensions/crew/runner/dependency-pins.mjs`. The pins are checked against `package-lock.json` in tests. Full tarball SHA-512 SRI is checked before decompression or archive parsing. Invalid, missing, timed-out or incompatible artifacts are unavailable, not substituted from the host installation. Archive extraction is bounded and rejects links, special entries and unsafe paths. There is no persistent dependency cache. The public artifacts—not host credentials or configuration—supply the exposed bytes. This does not assert that a public package cannot itself contain sensitive strings.

Bootstrap decompression and archive parsing currently run synchronously on the Crew host in a single parser (`extractVerifiedPackage`) and are capped at 32 MiB compressed and 128 MiB unpacked per artifact. Main-host measurements for the reviewed pins (excluding network) ranged from 2.26 ms to 94.76 ms; decompressed tar sizes were about 7.9 MB for Prettier and 25,024,512 bytes (about 25 MB, ~95 ms synchronous extraction) for the Pi SDK, the largest. Verified snapshots are kept in host memory for the life of the Crew host process, and failed packages are retried on the next preparation, so the extraction cost is paid once per package per process. Residual risk: while an artifact is extracted the host event loop is blocked, stalling other crews for that period (about 95 ms observed for the largest pin; the 128 MiB cap bounds memory, not latency). These are single-run observations, not a worst-case guarantee: changing pins requires renewed measurement or an asynchronous parser.

Available packages are read-only snapshots at `/opt/crew/dependency-sources/`; `manifest.json` lists versions, SRI and SHA-256 of each extracted file. Hashes describe exposed file identity; the SRI verifies the downloaded artifact. Source visibility does **not** install or make native modules and dependency trees runnable.

Each guest environment receives its own in-memory copy behind Gondolin's `ReadonlyProvider`. One provider is deliberately not shared between members, so no member's mount can alias another's; the cost is one copy per environment (about 37 MB for the current pins) held in host memory until that environment is disposed. The first preparation in a host process can wait up to 10 seconds per artifact (downloads run in parallel) for the registry before an artifact is reported unavailable. Crew additionally refuses every non-read open flag and the write/truncate methods of read handles. Refusals carry Gondolin's `EROFS` errno (30, code `ERRNO_30`, as Gondolin's own `ReadonlyProvider` produces), so guest commands report `Read-only file system`. Writing, appending, truncating, creating files or directories, removing, renaming, moving in or out, and hard or symbolic linking all fail. Observed guest semantics (Gondolin 0.14.0): `chmod` and `touch` on an **existing** snapshot file may exit 0, but they are metadata no-ops—mode, size and SHA-256 are unchanged (modification time is not asserted). Do not treat a zero exit from those commands as evidence of writability. The live test `tests/runtime/dependency-source-live.test.mjs` asserts each refusal and its `EROFS` class, the unchanged mode/size/hash after `chmod`/`touch`, and matching writable controls on `/workspace`.

When Prettier is available, format workspace files using guest bash, for example:

```sh
node /opt/crew/dependency-sources/prettier/bin/prettier.cjs --write /workspace/path/to/file.mjs
```

Do not use a host formatter fallback. If Prettier is unavailable, say so and request hosted CI or coordinator help. Focused tests may run in the guest only if their real prerequisites are present; an unavailable project dependency is **CI-required**, not a passing or skipped test. Do not manufacture skips.

The supported hosted path is the `CI` pull-request workflow (`.github/workflows/ci.yml`): its **Required tests (all except the excluded krun cases)** step runs `node --test` over the project test files, including focused tests under `tests/crew` and `tests/runtime`; it also boots the QEMU-backed live guest tests. `npm run format:check` is a separate workflow step. Push to the authorized branch and open a draft PR; use the existing pull-request checks and workflow-run failed-log operations to retrieve outcomes. CI's documented krun exclusion is unchanged and must not be represented as krun coverage. The live test is hermetic by default: it verifies and mounts the reviewed Prettier archive that `npm ci` recorded in npm's content-addressed cache (looked up by the pin's SRI, then checked by the same SRI and extraction path), so an unreachable registry cannot fail it; set `HALL_LIVE_REGISTRY_TESTS=1` to fetch every pin from the registry as a launch does. `tests/crew/dependency-source.test.mjs` proves each bound (32 MiB download and archive, 128 MiB unpacked, 12,000 entries), unknown-pin rejection and the fixed registry host and path without network. A focused test can also be run where prerequisites are installed with `node --test tests/crew/dependency-source.test.mjs tests/crew/dependency-mount.test.mjs tests/runtime/dependency-source-live.test.mjs`; this is not a substitute for the full required CI step.

Reports must distinguish **guest checks**, **Main-host evidence**, **hosted CI**, and **unperformed checks**, including failures and missing prerequisites. A host-side artifact or provider test is not evidence of guest execution or read-only enforcement in a running guest.
